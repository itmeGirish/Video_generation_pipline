# Fireship Format — Style Reference

Apply this when the video should follow the Fireship style: fast, dense, dry-funny,
zero filler. This is a STYLE layer on top of the pipeline rules — it changes pacing,
voice, and density, not the parser format (rules 04/05 still apply exactly).

Reference: Jeff Delaney's Fireship channel — the "X in 100 Seconds" and "Code Report"
series. Core feel: maximum information per second, deadpan humor, relentless pace.

---

## The core traits

1. **Cold open, zero intro.** No "hey guys, welcome back." First sentence is the
   topic or the hook. The viewer is already mid-idea by second one.
2. **Extreme density.** ~200–250 words per minute. Every sentence carries a fact.
   Cut anything that isn't information or a joke.
3. **Fast visual cuts.** ~10–15 visual changes per minute — a new beat every few
   seconds. Nothing sits on screen long. (In bullets: more, shorter beats.)
4. **Dry, self-aware humor.** One deadpan aside or punchline every ~20–30 seconds.
   Sarcasm about hype, "a new JS framework dropped this week" energy. Never forced.
5. **Show it, don't pad it.** On-screen code snippets, real UI, a quick diagram —
   then move on. The visual proves the point in a beat, then it's gone.
6. **Brutal brevity.** Short videos (often under ~3–4 min, "100 seconds" for a single
   concept). Tight is the whole brand. If a sentence can be shorter, shorten it.
7. **Cliffhanger momentum.** Each beat sets up the next; end on a quick payoff or a
   wry button, not a long outro.

---

## Voice rules (layer on rule 02)

- Spoken, peer-to-peer, never corporate. Contractions always.
- Punchy declaratives. Frequent very-short sentences. "It works. Mostly."
- Confident and a little irreverent — opinions, hot takes, mild roasting of hype.
- Humor is dry and fast: a clause, not a setup-and-punchline paragraph.
- Numbers and specifics over adjectives — density comes from concreteness.
- Drop a knowing aside, then immediately move on. Don't linger on the joke.

This raises the humor and pace well above the default preferences. Fireship mode
overrides "humor: sparingly" and "medium sentences" for the duration of the video.

---

## Structure rules (layer on rule 01)

- **Scene 1 = the hook in one line**, then straight into it. No context scene before
  the payoff starts.
- **Shorter scenes, more of them.** Each scene is one idea delivered fast.
- **More bullets per scene, each shorter** (~2–5s of screen time) to hit the
  10–15 cuts/min feel — but each beat still MEANS something (rule 03b applies).
- **End on a button** — a one-line verdict or a dry joke, then a fast CTA. No drawn-out
  conclusion.

---

## Animation rules (layer on rule 03)

- Bias to **code snippets, real UI, quick diagrams, and memes-as-illustration** over
  abstract metaphors — Fireship shows the actual thing.
- Keep the rule-03 standards: motion must mean something, show-don't-tell (no text
  walls), every beat Remotion-buildable. Fireship is dense but never a slide deck.
- Faster beats = make sure each still passes rule 03b (makes sense + fits + buildable).
  Speed is not an excuse for a beat that doesn't read.

---

## What still applies (do NOT override)

- **Real, sourced facts only** (rule 00). Fireship is fast but factually tight — the
  humor rides on accurate specifics, not invented numbers.
- **Parser format** (rules 04/05) — exact same syntax.
- **Animation validator** (rule 03b) and **human review** (rule 05b) — still run.

---

## Quick checklist — is it Fireship enough?

- [ ] Cold open — first line is the hook, no intro
- [ ] ~200+ words/min, every sentence carries a fact
- [ ] A dry aside/punchline roughly every 20–30s
- [ ] Short beats, fast cuts (more, shorter bullets)
- [ ] Shows real code/UI/diagram instead of describing it
- [ ] Tight total runtime, ends on a one-line button
- [ ] Still factually sourced, still passes format + animation validators
