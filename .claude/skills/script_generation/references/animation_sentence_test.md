# The Sentence Test — Visual Explanation vs Visual Noise

Worked good/bad pairs for the #1 animation-quality test (rule 03 "Clarity first",
gated by rule 03b Check A, implemented/verified in video_generation rules 21 + 23 V15).

> **⚠️ DERIVE, DON'T COPY.** These examples teach the **method** — turn a sentence into
> a literal depiction of its actions — NOT the specific visuals. Every script has
> different sentences, so every script gets different visuals. Do **not** reuse
> "task splits into Research/Coding/Validation" or "revenue bar grows" unless YOUR
> narration actually says that. Copying these visuals into an unrelated script is the
> exact "visual noise" failure this test exists to prevent. The transferable thing is
> the question — *"what sentence is this explaining?"* — applied to YOUR script.

## The test

For **every** animation bullet, ask:

> **"What sentence of the narration is this animation explaining?"**

If you can name the exact sentence/clause AND the visual is a play-by-play of it →
visual explanation. If you can't → **visual noise**, regardless of how rich or
animated it looks. Motion alone is not the bar.

This is the biggest difference between average AI-generated video and high-retention
YouTube (Fireship, 3Blue1Brown, MKBHD). They rarely animate just because the screen
feels empty — almost every visual maps to a specific sentence.

It catches the gap the other gates miss: a "futuristic city + floating AI brain + neon
particles" is moving, rich, and non-text — so it passes the freeze check (A4) and the
text-slide check (V12) — yet it explains nothing.

---

## Worked examples

### 1. AI agents
**Narration:** "Hermes receives a task, breaks it into subtasks, and assigns them to specialized agents."

✅ **Explanation** (each beat = one clause):
- user submits task
- task enters Hermes
- task splits into Research / Coding / Validation
- three agents work independently
- results merge back together

❌ **Noise:** futuristic city, floating AI brain, neon particles, robots walking — moving, but none depicts task decomposition or delegation.

### 2. Remote MCP server
**Narration:** "The client sends a request to the remote MCP server, which retrieves data from multiple tools."

✅ **Explanation:** client icon → request arrow → MCP server receives → connects to Database / Gmail / Slack → responses return → combined result sent back.

❌ **Noise:** server rack spinning, cloud icons floating, code rain — looks technical, teaches nothing.

### 3. Revenue growth
**Narration:** "The company grew from $2M to $20M ARR in three years."

✅ **Explanation:** timeline appears → revenue bar grows year by year → numbers tick up.

❌ **Noise:** dollar signs flying, CEO photo zoom, office stock footage — doesn't visualize the growth claim.

### 4. LLM hallucination
**Narration:** "When the model lacks information, it may generate confident but incorrect answers."

✅ **Explanation:** question enters model → knowledge base shown empty → model generates an answer → red warning icon appears.

❌ **Noise:** AI brain pulsing, glowing circuit board, abstract particles — generic AI mood.

### 5. Database query
**Narration:** "The application queries the database and returns matching customer records."

✅ **Explanation:** search box → SQL query sent → database searched → matching rows highlighted → results returned.

❌ **Noise:** programmer typing, terminal scrolling, coffee cup — related to software in general, not this concept.

---

## The rule of thumb

For each bullet, write the one sentence it explains next to it. If the visual is a
literal depiction of that sentence's actions, it passes. If the visual is "looks
technical / looks AI" but you can't tie it to the words, redesign it — animate the
clauses in sequence instead (one beat per clause).

**The visuals come from YOUR script's sentences, never from this file.** If two
different scripts produce the same animation, at least one of them isn't depicting its
own narration — that's the failure, not the goal.
